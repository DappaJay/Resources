Built for: Customer Enquiry Handler

How this tool works

A customer enquiry handler typically contains two separate AI steps - each with its own cost:

  • Step 1 - Classify: the AI reads the incoming message and decides what type of enquiry it is. This step is quick, cheap, and produces a short output.
  • Step 2 - Respond: the AI uses the classification result and the original message to draft a reply. This step does the heavy lifting and costs more.

The total cost per enquiry is the sum of both steps. Configure each step below using what you know about your automation, then read the results at the bottom.

Why AI costs are different to traditional software costs. Traditional software is priced by seat or licence - predictable, budgetable, fixed. AI is priced by consumption - every token sent and received costs money, and that cost varies with how the system is built, how it is used, and how much traffic it handles. That is why this tool exists and why comparing scenarios matters more than relying on a single point estimate. Use the outputs to stress-test decisions - not as a precise cost forecast.
What is a token? AI models charge by the token - roughly one token per word in plain English. Every token sent in and every token written back costs a tiny amount. These amounts add up fast at volume. This tool calculates what you will pay based on how your automation is designed, which model you use, and how often it runs.
This tool models a non-agentic automation. A two-step classify-and-respond pipeline is a fixed linear workflow - one API call to classify, one to reply, predictable token costs every time. This is different from agentic AI, where a model takes autonomous multi-step actions, calls tools, and loops back on itself. Agentic workflows can use 10 to 1,000 times more tokens per task and are a significant contributing factor in the AI budget overruns making headlines in 2026. If you are evaluating an agentic build, the cost model is significantly different and not covered by this tool.

Feeding this into the AI Automation Cost Estimator

This tool is most useful for comparing scenarios - for example, what happens if volume doubles, or if you switch model - rather than predicting an exact monthly bill.

Take the monthly token cost figure from the results above and enter it directly into the "Estimated token costs per month" field in the AI Automation Cost Estimator. No further calculation is needed - the monthly figure is already shown.

Then set the build quality dropdown in that tool as follows:

  • Well-architected without caching (1.5x) - if your build uses RAG and efficient routing but no prompt caching. This is what this tool models.
  • Well-architected with caching (1x) - if your build also implements prompt caching. Your actual costs will be approximately 30 to 50% lower than shown here.
  • Unknown/unaudited (3x) - if you are unsure how your automation is built. Use this as a conservative estimate.

Notes and assumptions

1 Monthly volume is assumed flat across all 12 months with no seasonality, growth or downtime. Seasonal businesses should use their true average monthly figure.
2 The original message length selection in Step 1 feeds directly into Step 2 input token count. Selecting the wrong band has an outsized effect on total cost accuracy across both steps.
3 This tool models full knowledge base injection on every call. A well-architected build using RAG retrieves only the relevant section, which can reduce knowledge base token costs by 80 to 90%.
4 System prompt tokens are sent to the AI on every single call. A longer system prompt adds cost on every enquiry.
5 Output tokens cost significantly more per token than input tokens at every provider - up to 5x more depending on the model. Response length has a disproportionate effect on total cost compared to an equivalent increase in input length.
6 Model tier recommendations are a judgement-based starting point and not a universal standard. The right model depends on your specific use case and the quality of output required.
7 Token counts shown are estimates based on your selections. Actual counts vary by content type - technical content, numbers, punctuation and non-English text tokenise differently to plain English prose. Non-English languages can use 2 to 3 times as many tokens per word as English, which would significantly increase costs beyond what this tool shows.
8 This tool models a single enquiry processed once from start to finish. Automations handling ongoing conversation threads accumulate context across exchanges and will incur higher costs than shown.
9 The total cost assumes every enquiry completes both steps. If your automation routes some enquiries to a human after Step 1, actual Step 2 costs will be proportionally lower.
What this tool does not include
API retry costs (failed calls that re-run) - Moderation or safety filter calls - Tool use or function calling overhead - Vendor platform fees (Make.com, Zapier subscriptions) - Prompt truncation costs - Human review time - Token counts for non-English, technical, or heavily punctuated text may be higher than shown (non-English text and numbers tokenise less efficiently than plain English prose)
